Question 1.
Topic: java-basics
```
void main() {
    int i = 5;
    int j = i++ + ++i;
    int k = i-- - --i;
    IO.println(i + " " + j + " " + k);
}
```
What is the result?
A. `5 11 2`
B. `5 12 2`
C. `6 12 0`
D. `5 12 0`
Check: output
[THINK]
The answer is B. i++ yields 5 and makes i 6; ++i makes i 7 and yields 7, so j is 12. Then i-- yields 7 and makes i 6; --i makes i 5 and yields 5, so k is 2, and i ends at 5.

Question 2.
Topic: java-basics
```
void main() {
    int a = 0, b = 0;
    boolean r = (a++ > 0) && (b++ > 0);
    boolean s = (a++ > 0) | (b++ > 0);
    IO.println(a + " " + b + " " + r + " " + s);
}
```
What is the result?
A. `2 1 false true`
B. `2 2 false true`
C. `2 0 false true`
D. `1 1 false false`
Check: output
[THINK]
The answer is A. && short-circuits: the left side is false, so b++ doesn't run. The single | always evaluates both sides: a++ yields 1, which is greater than 0, and b++ runs once.

Question 11.

        case Integer i -> "int";
        case String s -> "string " + s.length();
        case null, default -> "other";
    };

void main() {

```

A. `int other string 2 other`
B. `positive other string 2 other`
C. A NullPointerException is thrown
D. Compilation fails
Check: output
[THINK]
The answer is A. -1 fails the guard and matches the unguarded Integer case. case null, default handles both null and the Double. Writing case null, default before the Integer cases wouldn't compile, because it would dominate them.

Question 12.

```
void main() {
    int x = 0;
    while (true) {
        x++;
        if (x > 2) break;
    }
    IO.println(x);
    for (;;) { }
    IO.println("end");
}
```
What is the result?
A. `3` and the program keeps running
B. `3 end`
C. `2` and the program keeps running
D. Compilation fails
Check: compile-error
[THINK]
The answer is D. The while loop has a break, so the code after it is reachable. But for (;;) without a break never completes, so the last println is unreachable, which is a compile error.

Question 13.
Topic: java-oop
```
// a/Parent.java
package a;
public class Parent {
    protected int value = 1;
}

// b/Child.java
package b;
import a.Parent;
public class Child extends Parent {
    void test(Parent p, Child c) {
        int v1 = value;        // line 1
        int v2 = c.value;      // line 2
        int v3 = p.value;      // line 3
        int v4 = this.value;   // line 4
    }
}
```
Which line fails to compile?
A. Line 1
B. Line 2
C. Line 3
D. Line 4
Check: none
[THINK]
The answer is C. In a different package, a subclass can access a protected member only through a reference of its own type or a subtype. p is a Parent reference, so p.value doesn't compile.

Question 16.

```
import java.util.*;

    static class Key {
        final int id;
        Key(int id) { this.id = id; }

        Set<Key> set = new HashSet<>();

```

The answer is D. equals(Key) overloads equals instead of overriding equals(Object). HashSet calls equals(Object), inherited from Object, which compares references, so both keys are added. The direct call picks the overload with the more specific type and returns true.

void main() {

Question 24.
Topic: java-exceptions
```
public class Main {
    static class AppException extends Exception {
        AppException(String m) { super(m); }
    }
    static void run() { IO.print("run "); }
    public static void main(String[] args) {
        try {
            run();
        } catch (AppException e) {
            IO.print("caught ");
        }
    }
}
```
What is the result?
A. `run`
B. `run caught`
C. Compilation fails
D. An AppException is thrown
Check: compile-error
[THINK]
The answer is C. AppException is a checked exception, and nothing in the try block can throw it. Catching a checked exception that can't be thrown is a compile error. Catching Exception or a RuntimeException would compile.

Question 25.

        IO.println(log);

```
What is the result?
A. `1345`
B. `135`
C. `1235`
D. `13`
Check: output
[THINK]
The answer is B. The RuntimeException doesn't match the IllegalArgumentException catch. finally runs, then the exception leaves the method, skipping the line that adds 4, and main catches it.
