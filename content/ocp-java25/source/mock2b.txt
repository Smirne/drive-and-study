Question 1.
Topic: java-collections
```
import java.util.*;

void main() {
    Deque<Integer> d = new ArrayDeque<>();
    d.push(1); d.offer(2); d.offerFirst(3); d.addLast(4);
    IO.println(d.pop() + " " + d.pollLast() + " " + d.peek() + " " + d);
}
```
What is the result?
A. `3 4 1 [1, 2]`
B. `1 4 2 [2]`
C. `3 2 1 [1, 4]`
D. `4 1 3 [3, 2]`
Check: output
[THINK]
The answer is A. push and offerFirst add at the front, offer and addLast at the end, giving 3, 1, 2, 4. pop removes from the front, pollLast from the end, and peek reads the front without removing it.

Question 14.
Topic: java-concurrency
```
import java.util.*;
import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) throws Exception {
        List<Callable<String>> tasks = List.of(() -> "a", () -> "b", () -> "c");
        try (var ex = Executors.newFixedThreadPool(2)) {
            var sb = new StringBuilder();
            for (Future<String> f : ex.invokeAll(tasks)) sb.append(f.get());
            IO.println(sb + " " + ex.isShutdown());
        }
    }
}
```
What is the result?
A. `abc true`
B. The letters in an unpredictable order, followed by false
C. `abc false`
D. Compilation fails
Check: output
[THINK]
The answer is C. invokeAll waits for all tasks and returns their Futures in the same order as the tasks, whatever order they ran in. The executor is still open inside the try block; close shuts it down at the end.

```
import java.util.concurrent.locks.*;

public class Main {
    public static void main(String[] args) {
        Lock lock = new ReentrantLock();
        if (lock.tryLock()) {
            try { IO.print("locked "); } finally { lock.unlock(); }
        }
        lock.unlock();
        IO.println("end");
    }
}
```
What is the result?
A. `locked end`
B. `locked` followed by an IllegalMonitorStateException
C. `end`
D. The program waits forever
Check: exception IllegalMonitorStateException
[THINK]
The answer is B. tryLock succeeds and the finally block releases the lock. The second unlock is called by a thread that no longer holds the lock, which throws IllegalMonitorStateException.

Question 21.
Topic: java-io
```
import java.io.*;

public class Main {
    static class Base { int b = 1; Base() { b = 2; } }
    static class Item extends Base implements Serializable {
        int x = 3; transient int y = 4; static int z = 5;
        Item() { x = 6; }
    }
    public static void main(String[] args) throws Exception {
        var item = new Item();
        item.b = 7; item.x = 8; item.y = 9;
        var bytes = new ByteArrayOutputStream();
        try (var out = new ObjectOutputStream(bytes)) { out.writeObject(item); }
        Item.z = 10;
        try (var in = new ObjectInputStream(new ByteArrayInputStream(bytes.toByteArray()))) {
            Item copy = (Item) in.readObject();
            IO.println(copy.b + " " + copy.x + " " + copy.y + " " + Item.z);
        }
    }
}
```
What is the result?
A. `7 8 9 5`
B. `2 6 4 10`
C. `7 8 0 10`
D. `2 8 0 10`
Check: output
[THINK]
The answer is D. Base isn't serializable, so its no-argument constructor runs during deserialization and sets b to 2. x is restored from the stream, y is transient and gets 0, and the Item constructor doesn't run. Static fields aren't serialized at all.
