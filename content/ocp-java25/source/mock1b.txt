Question 1.
Topic: java-collections
```
import java.util.*;

void main() {
    String[] arr = {"x", "y", "z"};
    List<String> a = Arrays.asList(arr);
    a.set(0, "q");
    List<String> b = List.copyOf(a);
    arr[1] = "w";
    IO.println(a + " " + b);
}
```
What is the result?
A. `[q, y, z] [q, y, z]`
B. `[q, w, z] [q, w, z]`
C. `[q, w, z] [q, y, z]`
D. An UnsupportedOperationException is thrown
Check: output
[THINK]
The answer is C. Arrays.asList returns a list backed by the array: set works, and changes to the array show through the list. List.copyOf makes an independent unmodifiable copy, taken before arr[1] changed.

Question 4.

```
    Map<String, Integer> m = new TreeMap<>();
    for (String w : "the cat and the hat".split(" "))
        m.merge(w, 1, Integer::sum);
    m.computeIfPresent("and", (k, v) -> null);
    m.putIfAbsent("cat", 9);

```
What is the result?
A. `{and=null, cat=1, hat=1, the=2}`

The answer is D. merge counts the words. When the remapping function of computeIfPresent returns null, the entry is removed. putIfAbsent does nothing because cat is already mapped. A TreeMap keeps its keys sorted.

Question 15.
Topic: java-concurrency
```
import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) throws Exception {
        try (ExecutorService ex = Executors.newVirtualThreadPerTaskExecutor()) {
            Future<Integer> f = ex.submit(() -> 6 * 7);
            Future<?> g = ex.submit(() -> { throw new IllegalStateException("bad"); });
            IO.println(f.get());
            try {
                g.get();
            } catch (ExecutionException e) {
                IO.println(e.getCause().getMessage());
            }
        }
    }
}
```
What is the result?
A. `42` followed by an uncaught IllegalStateException
B. `42 bad`
C. `42 null`
D. Compilation fails
Check: output
[THINK]
The answer is B. Future.get returns the Callable's result. When a task throws, get wraps the exception in an ExecutionException, whose cause is the original exception. Closing the executor waits for the tasks.

Question 17.
Topic: java-concurrency
```
public class Main {
    static final ScopedValue<String> USER = ScopedValue.newInstance();
    static String who() { return USER.isBound() ? USER.get() : "nobody"; }
    public static void main(String[] args) {
        ScopedValue.where(USER, "ann").run(() -> {
            IO.print(who() + " ");
            ScopedValue.where(USER, "bob").run(() -> IO.print(who() + " "));
            IO.print(who() + " ");
        });
        IO.println(who());
    }
}
```
What is the result?
A. `ann bob bob nobody`
B. `ann bob ann ann`
C. `ann bob ann nobody`
D. A NoSuchElementException is thrown
Check: output
[THINK]
The answer is C. A binding lasts only for the run call. The nested where rebinds USER for the inner scope only; afterwards ann is visible again. Outside, USER is unbound, so isBound is false.

Question 19.
Topic: java-modules
```
// module-info.java of com.shop.core
module com.shop.core {
    requires transitive com.shop.model;
    exports com.shop.core.service;
}

// module-info.java of com.shop.app
module com.shop.app {
    requires com.shop.core;
    exports com.shop.app.api;
}
```
Which statement is true?
A. Code in com.shop.app can use the public types exported by com.shop.model
B. com.shop.app must also require com.shop.model to use its types
C. Modules that require com.shop.app can also read com.shop.core
D. com.shop.app re-exports the package com.shop.core.service
Check: none
[THINK]
The answer is A. requires transitive in com.shop.core gives implied readability of com.shop.model to every module that requires com.shop.core. com.shop.app requires com.shop.core without transitive, so its own readers don't get com.shop.core. Exports are never inherited.

Question 24.
Topic: java-locale
```
import java.text.*;
import java.util.*;

void main() throws ParseException {
    var us = NumberFormat.getInstance(Locale.US);
    var de = NumberFormat.getInstance(Locale.GERMANY);
    Number n = us.parse("1,234.5abc");
    IO.println(de.format(n) + " " + new DecimalFormat("00.0").format(3.14159));
}
```
What is the result?
A. A ParseException is thrown
B. `1,234.5 3.1`
C. `1.234,5 03.1`
D. `1234,5 03.14`
Check: output
[THINK]
The answer is C. parse stops at the first character it can't use, so it reads 1234.5. The German format uses a dot for grouping and a comma for decimals. In a DecimalFormat pattern, 0 always prints a digit, so 3.14159 becomes 03.1.
