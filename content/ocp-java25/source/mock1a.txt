Question 1.
Topic: java-basics
```
void main() {
    char c = 'a';
    c += 2;
    int i = c + 1;
    IO.println(c + " " + i);
}
```
What is the result?
A. `c 100`
B. `99 100`
C. `c d`
D. Compilation fails
Check: output
[THINK]
The answer is A. Compound assignment casts back to char, so c becomes 'c'. In c plus one, the char is promoted to int: 99 plus 1 is 100. In the println, c is concatenated to a String, so it prints as a character.

Question 13.
Topic: java-flow
```
void main() {
    int count = 0;
    outer:
    for (int i = 0; i < 3; i++) {
        for (int j = 0; j < 3; j++) {
            if (j == i) continue outer;
            if (i + j > 3) break outer;
            count++;
        }
    }
    IO.println(count);
}
```
What is the result?
A. `2`
B. `4`
C. `3`
D. `5`
Check: output
[THINK]
The answer is C. When j equals i, the outer loop moves on, so the inner loop only counts values of j below i. That's none for i = 0, one for i = 1 and two for i = 2. The sum never exceeds 3, so the break never runs.

A. `walk+swim`

[THINK]

Question 23.
Topic: java-exceptions
```
public class Main {
    record Res(String n) implements AutoCloseable {
        public void close() { IO.print("close" + n + " "); }
    }
    public static void main(String[] args) {
        try (var a = new Res("A"); var b = new Res("B")) {
            IO.print("body ");
            throw new IllegalStateException();
        } catch (IllegalStateException e) {
            IO.print("catch ");
        } finally {
            IO.print("finally");
        }
    }
}
```
What is the result?
A. `body catch closeB closeA finally`
B. `body closeA closeB catch finally`
C. `body catch finally closeB closeA`
D. `body closeB closeA catch finally`
Check: output
[THINK]
The answer is D. Resources are closed in reverse order of declaration, as soon as the try block ends, before catch and finally run.

Question 24.

```
public class Main {

        try {
            return x;
        } finally {
            x = 2;
        }
    }
    static int g() {
        try {
            throw new RuntimeException("boom");
        } finally {
            return 3;
        }
    }
    public static void main(String[] args) {
        IO.println(f() + " " + g());
    }
}
```
What is the result?
A. `2 3`
B. `1 3`
C. A RuntimeException with the message boom is thrown
D. Compilation fails
Check: output
[THINK]
The answer is B. In f, the return value is evaluated before finally runs, so changing x afterwards doesn't affect it. In g, the return in finally discards the exception.

```

public class Main {
    static void read() throws FileNotFoundException { throw new FileNotFoundException(); }
    public static void main(String[] args) {
        try {
            read();
        } /*?*/ {
            IO.println("handled");
        }
    }
}
```
Which two clauses can replace /*?*/ so that the code compiles? Choose two.
A. `catch (IOException | RuntimeException e)`
B. `catch (FileNotFoundException | IOException e)`
C. `catch (java.sql.SQLException e)`
D. `catch (Exception e)`
E. `catch (RuntimeException e)`
Check: options
[THINK]
The answers are A and D. Option A is a valid multi-catch of two unrelated types, and IOException covers FileNotFoundException. Option D catches everything. Option B combines related types. Option C catches a checked exception the try block can't throw, and leaves FileNotFoundException unhandled. Option E doesn't handle the checked exception.
