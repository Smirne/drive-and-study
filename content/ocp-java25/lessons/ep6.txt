Java 25 Developer Professional. Episode six. Records, sealed types, enums, nested classes, and compact source files.

This episode covers the special kinds of types: records, sealed classes and interfaces, enums, and nested classes. It ends with compact source files and instance main methods, new in Java 25.

Records first. A record is a transparent carrier for immutable data. You declare it with the record keyword, a name, and a list of components in parentheses, like record Point, int x, int y. From that header the compiler generates: a private final field for each component; a public accessor method for each, with the same name as the component, so x open close parentheses, not getX; a canonical constructor that takes all components in order; and equals, hashCode and toString based on all components. toString prints the record name followed by the components in square brackets, like Point open square bracket x equals one, comma y equals two.

The restrictions matter. A record is implicitly final, so it can't be extended, and it can't extend another class, because it already extends java dot lang dot Record. It can implement interfaces. It can't declare instance fields outside the header, though it can have static fields, static methods, instance methods, and nested types. Instance initializer blocks aren't allowed.

Constructors. You can write the canonical constructor in full, assigning each field. Or you can write a compact canonical constructor: the record name followed directly by braces, with no parameter list. It runs before the fields are assigned, and its job is to validate or normalize the parameters. Inside it you assign the parameters themselves, not the fields: writing this dot x equals something in a compact constructor doesn't compile, because the fields are final and assigned automatically at the end. You can also add other constructors, but each one must call another constructor with this, eventually reaching the canonical one.

You can override the accessors, equals, hashCode and toString. An overridden accessor must be public and return exactly the component's type. Records are immutable only in a shallow way: if a component is a mutable list, the list itself can still change unless you copy it, for example with List dot copyOf in the compact constructor.

Local records, declared inside a method, are allowed and implicitly static, so they can't capture local variables of the enclosing method.

Sealed types. A sealed class or interface restricts which types may extend or implement it. You write sealed, and a permits clause listing the allowed subtypes. If all subtypes are in the same source file, the permits clause can be omitted. Each permitted subtype must directly extend the sealed type and must itself be declared final, sealed, or non-sealed. Records are implicitly final, so they qualify without a keyword. Enums too. A non-sealed subtype reopens the hierarchy below it.

Where can permitted subtypes live? In the same module as the sealed type, or, if the code is in the unnamed module on the class path, in the same package. A permitted class that doesn't extend the sealed type, or a class that extends it without being listed, doesn't compile.

The payoff is exhaustiveness: a switch over a sealed type that covers all permitted subtypes needs no default. Combined with record patterns, this is how modern Java models data with a fixed set of variants.

Enums. An enum declares a fixed set of constants. Its constructor is implicitly private; you can't call it with new. An enum can have fields, constructors, methods, and can implement interfaces, but it can't extend a class. Each constant can provide its own body, which is how you implement an abstract method declared in the enum. The static method values returns an array of the constants in declaration order; valueOf converts a name, and throws IllegalArgumentException if the name doesn't match exactly, case included. ordinal gives the zero-based position, and name gives the declared name. Enums compare safely with double equals.

In a switch on an enum, the case labels use the bare constant names; since Java 21 the qualified name is also allowed.

Nested classes come in four kinds. A static nested class is like a top-level class placed inside another, and it can access the outer class's private static members. An inner class, non-static, is tied to an instance of the outer class: you create it from outside with outer instance dot new Inner. Inside, the outer instance is available as Outer dot this. Since Java 16, inner classes can declare static members. A local class is declared inside a method, and an anonymous class is declared and instantiated in one expression. Local and anonymous classes, like lambdas, can use local variables of the enclosing method only if they're final or effectively final, meaning they're never reassigned.

Interfaces, enums and records declared inside a class are always implicitly static.

Now, compact source files and instance main methods, final in Java 25. A source file can contain methods and fields without any enclosing class declaration. The compiler creates an implicitly declared class around them. This class is final, lives in the unnamed package, and can't be referenced by name from other code. It must have a main method that the launcher can use. The file automatically imports all packages exported by the java dot base module, and you can use the IO class from java dot lang for simple console input and output: IO dot println, IO dot print, and IO dot readln.

Instance main methods apply to any class, not only compact files. The launcher looks for a main method that's not private. It can be static or not, and it can take a String array or no parameters. If both a String array version and a no-parameter version exist, the one with the String array is chosen. If the chosen main is an instance method, the launcher creates an instance using a non-private no-argument constructor, so the class needs one.
