Mock exam two, part one.

Question 1.
Topic: cd-apps
A chatbot keeps the conversation history on the client and sends only the newest user message to the API. Users complain that Claude forgets what they said two turns ago. What's the cause?
A. The model's context window is too small
B. Prompt caching expired between turns, so the earlier messages were dropped from memory
C. The temperature is set too high
D. The API is stateless, so the full conversation history must be sent with every request
[THINK]
The answer is D. Each request must include the whole conversation. Caching reduces the cost of resending it.

Question 2.
Topic: cd-apps
A request returns stop reason refusal with HTTP status two hundred. The application currently treats every two hundred as a valid answer and stores it as structured data. What should it do?
A. Retry the same request in a loop until the stop reason changes, then store the result
C. Treat it as a network error
B. Detect the refusal, and handle it, for example with a fallback model
D. Lower max tokens
[THINK]
The answer is C. A refusal is a normal response, not an error, and its content may not match the expected schema.

Question 3.
Topic: cd-apps
An agent using the server-side web search tool returns a response with stop reason pause turn. What should the application do?
A. Treat the response as final
B. Start a new conversation without the search tool, passing the partial answer as context
C. Send the assistant content back unchanged, with the same tools, so the server-side search loop can continue
D. Add a tool result block for each search
[THINK]
The answer is C. Pause turn means the server tool loop hit its iteration limit. Server tools don't need client tool results.

Question 4.
Topic: cd-apps
A report generator needs outputs that may take fifteen minutes to produce. Non-streaming requests time out. Which two approaches fit? Choose two.
A. Use streaming, collecting the final message with the SDK helper
E. Split the report request across several API keys
C. Retry the non-streaming request with a longer client timeout until it succeeds
D. Lower max tokens so the report is always short
B. Use the Message Batches API if nobody waits for the result
[THINK]
The answers are A and E. Long requests should stream, or go through batches. The SDKs refuse non-streaming requests expected to exceed about ten minutes.

Question 5.
Topic: cd-apps
A streaming client accumulates input JSON deltas for a tool call and tries to parse each fragment as it arrives, failing with parse errors. What's the correct handling?
A. Concatenate the fragments
B. Switch tool choice to none, so no tool input is streamed
C. Parse only the first fragment
D. Disable streaming for all requests that use tools, and keep it only for plain text answers
[THINK]
The answer is A. Fragments aren't valid JSON alone. Accumulate, then parse when the block ends, or use the SDK helpers.

Question 6.
Topic: cd-apps
A streaming response returned HTTP two hundred, but the user saw nothing after a few sentences. Logs show an error event of type overloaded in the middle of the stream. What does this tell the team?
A. The API key is invalid
B. Errors can occur mid-stream after the two hundred status, so the client must handle error events in the stream and recover
C. The model refused the request partway through the answer
D. The request exceeded the byte size limit, which is only checked once streaming has started

The answer is B. Mid-stream errors arrive as error events, not status codes. Handle them, and resume from the partial text if appropriate.

Question 12.
Topic: cd-apps
A team caches a large set of documents for a batch of thirty thousand requests that will be processed over several hours. Cache hits are low. What should they change?
A. Disable caching for batches
B. Use the one-hour cache lifetime
C. Put the documents after the question, so the prefix is shorter and cheaper to write

The answer is B. Batch requests may be processed far apart in time, so the five-minute cache often expires. Streaming isn't supported in batches.

Question 14.
Topic: cd-model
Which two changes invalidate the cached prompt prefix for the whole request? Choose two.
C. Adding a new user message at the end
B. Adding a tool to the tools list
A. Changing a tool's description
D. Changing the text of the latest user question
E. Reading the cache twice within five minutes
[THINK]
The answers are B and C. Tools come first in the prefix, so any change to tool definitions invalidates everything after them. New messages at the end extend the prefix.

Question 15.
Topic: cd-model
Usage for a request shows cache creation input tokens and cache read input tokens both at zero, even though cache control is set. What's the most likely cause?
A. The model doesn't support caching
C. The breakpoint is on the system prompt, and system prompts can't be cached on their own
B. The cached prefix is shorter than the minimum cacheable length, so it's silently not cached at all
D. The cache was read successfully
[THINK]
The answer is C. Prefixes below the minimum length are silently not cached, without an error.

Question 16.
Topic: cd-model
A team's agent system prompt starts with the current timestamp, followed by twenty thousand tokens of stable instructions. Cache reads are always zero. What's the fix?

C. Remove the instructions, and keep only the timestamp at the top
D. Add a breakpoint before the timestamp only, and keep the timestamp at the top for context

The answer is A. Changing content at the start of the prefix invalidates everything after it. Stable content first, variable content last.

Question 17.

Question 18.
