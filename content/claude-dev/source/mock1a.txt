Mock exam one, part one.

Question 1.
Topic: cd-apps
A support assistant streams its answers. Users report that long answers sometimes end mid-sentence, with no error shown. Logs show the client treats the first content block stop event as the end of the response. What should the team change?
A. Lower the temperature so answers become shorter and fit in one block
B. End at message stop, and check the stop reason in message delta
C. Disable streaming and wait for the full response in one call, keeping the current completion logic
D. Add a stop sequence at the end of the system prompt
[THINK]
The answer is B. Content block stop ends one block only. The message ends at message stop, and the stop reason in message delta reveals truncation. Option C hides the symptom and still ignores the stop reason.

Question 2.
Topic: cd-apps
An application sends sixty independent summarization requests one after another, and the page takes minutes to load. A developer proposes sending all sixty at once with no limit. A user is waiting for the page. What should the team do?
A. Send all sixty at once and ignore rate limit errors
B. Move the requests to the Message Batches API, which halves the cost and handles volume
C. Send them with bounded concurrency and backoff on rate limits
D. Combine all sixty documents into one request with a larger max tokens
[THINK]
The answer is C. Unbounded parallelism triggers four twenty-nine errors. Batches can take hours, which doesn't fit a waiting user.

Question 3.
Topic: cd-apps
A team stores an invoicing prompt in a database table that product managers edit directly. The model is referenced through an alias that moves to newer snapshots. Output quality changed twice this month without any deploy. Which two changes address the root causes? Choose two.
A. Pin the model I D, changing it only after a passing evaluation
B. Keep the alias so fixes arrive automatically, but restrict who can edit the database table
C. Version-control the prompt, with a regression evaluation before release
D. Lower the temperature to zero for all invoicing requests, so the output is fully deterministic
E. Add a disclaimer to every generated invoice
[THINK]
The answers are A and C. A moving alias and untracked prompt edits are both sources of silent drift. Restricting editors leaves the alias problem, and temperature doesn't address either cause.

Question 4.
Topic: cd-apps
After Claude requests two tools in one response, the application sends a user message containing a text block that says "Here are the results", followed by two tool result blocks. The API returns a four hundred error. What's the fix?
A. Send each tool result in its own separate user message, keeping the explanatory text in the first
B. Set tool choice to none for the follow-up request
C. Mark both tool results with is error set to true

Question 5.
Topic: cd-apps
A document analysis feature fails with a four hundred error, "prompt is too long", on very large PDFs. The team plans to raise max tokens. What's the correct response?
A. Raise max tokens to the model's maximum output, so the analysis has room for long documents
B. Count input tokens, then split or trim the document
C. Retry the same request with exponential backoff, since large documents often time out on the first try
D. Switch to streaming to avoid the limit
[THINK]
The answer is B. Max tokens limits output, not input. A four hundred isn't fixed by retrying, and streaming doesn't change the input size.

Question 6.
Topic: cd-apps
A company processes four hundred thousand catalog items overnight, and also lets editors regenerate single descriptions interactively during the day. What's the best combination?
A. Batches overnight, and streamed real-time requests for editors
B. Real-time requests for both, with unlimited parallelism
C. The Message Batches API for both workloads
D. Streaming for the overnight job, to avoid timeouts, and batches for the editors, to cut the cost of their many regenerations

The answer is A. Batches give half price for work nobody waits for. Editors waiting for a result need real-time responses, ideally streamed.

Question 7.
Topic: cd-apps
A meter-reading feature sends twelve-megapixel photos and is slow and expensive. A test showed that one-megapixel versions give the same accuracy. What should the team do?
A. Send the images by URL instead of base64 to reduce tokens
B. Switch to a larger model to process images faster
C. Downscale the images on the client before sending them
D. Convert the photos to PDF documents, which are processed more efficiently than raw images
[THINK]
The answer is C. Image token cost and latency scale with pixels. A URL only changes how the image travels, not its token cost.

Question 8.
Topic: cd-apps
A web front end calls the Claude API directly from the browser with the company's API key, and requests are rejected with a CORS error. What's the right change?
A. Add the browser's domain to an allow list in the API key settings, so the CORS check passes for that site
B. Use an admin key, which is allowed from browsers
C. Move the key to a cookie
D. Have the browser call your back end, which holds the key
[THINK]
The answer is D. Keys must never reach the client. The back end authenticates the user, applies limits and holds the key.

Question 9.
Topic: cd-apps
A batch of ten thousand requests finishes. The team reads the results file and writes each result to the database row at the same position as the request. Some rows now contain the wrong summaries. Why?
A. Batch results aren't guaranteed to come back in request order, so each result must be matched to its request by custom I D

Question 10.

Question 13.

An insurance company uses the most capable model to extract twelve fields from claim forms. An evaluation on five hundred real forms shows the fastest model matches its accuracy. Question 14.

A thinking model writing long reports frequently stops with the max tokens stop reason, even though the visible text is short. Why?
A. The system prompt is too long

Question 15.

A team caches a long system prompt plus a document set. Their only cache breakpoint is placed after the user's question at the end of the request. Usage shows cache creation tokens on every call, and almost no cache reads. What should they do?

The answer is C. A breakpoint after content that changes every request makes every prefix unique. The lifetime isn't the problem here.

Question 16.

A report generator calls the API every twenty minutes with the same forty thousand token prefix. Cache writes appear on every call, never reads. What's the most likely fix?
A. Use the one-hour cache lifetime

Question 18.

Question 21.

Question 22.

An inventory system consumes Claude's JSON output automatically. Occasionally a response is cut off and the parser crashes. The request already uses a JSON schema output format. What's the best approach?

Question 27.

Question 28.

A team builds one MCP server for its ticket system, to be used from developers' laptops in Claude Code and from a cloud-hosted agent. Which two design choices fit? Choose two.

Question 29.
Topic: cd-tools
An agent connected to six MCP servers has around two hundred tools. Each request carries tens of thousands of tokens of tool definitions, and the agent often picks the wrong tool. What should the team do?
A. Shorten every description to one line
B. Enable tool search with deferred loading
C. Force tool choice to any, so the agent must always pick one of the two hundred tools
D. Move the agent to a model with a larger context window, so all definitions fit comfortably

The answer is B. Tool search loads only the tools needed for the request, reducing tokens and improving selection. Short descriptions make selection worse.
